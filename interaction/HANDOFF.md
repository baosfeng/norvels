## 4. 开发怎么用（不要跳这一步）

见 [DEVELOPER.md](DEVELOPER.md)。三条最容易漏的：

1. **锚点落到代码**：给节点加 `data-od-id="C-nn"`，`odops parity` 才比得了；`C-xx` 是设计与实现的对账键，**不是产品 DOM 命名要求**。
2. **触发要逐条实现**：click / hover / focus / 键盘 四类是桌面端底线，只做 click = 未完成。
3. **移除后五问**：撤销窗口 / 焦点去向 / 滚动位置 / 计数联动 / 列表归属——这五项是最常漏的。

## 7. 两条通用判据（本轮踩出来的，后续复用）

1. **「标现有但产品没实现」是最高危缺陷**——开发看到「现有」就跳过，结果漏做且无从对账。机器门禁（ixcheck）**永远查不出**这类，只能靠拿作者自己的 `00-features.md` 反打契约找口径矛盾。
2. **凡是「不可恢复 + 数字/对象名出现在提示里」的地方，数字与对象名必须来自同一数据源，写死即 P0。**
3. **不给不可交互元素编交互**——只读浮层（toast、徽标）没有可聚焦元素，就不该有 hover/focus 行；补一行假焦点环比缺一行更坏。
4. **禁用原因必须常驻可见，不能藏在悬停/长按里**——触屏没有悬停，藏起来等于没有。
