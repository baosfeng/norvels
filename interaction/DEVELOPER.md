> 读者：实现本项目的开发 agent。**设计已冻结在 `interaction/`，实现方不重新做设计判断。**
> 规范：`designing-interactions` 技能的 `developer.md`；本文件只写**本项目专属**的落地口径。

## 1 锚点落到代码

契约的 `C-nn` 是**设计与实现之间的对账键**，不是产品 DOM 的命名要求。
- 给对应节点加 `data-od-id="C-nn"`（与契约逐字相同），这样 `odops parity` 能机器对表；
- **不要**改产品里既有的 `data-testid` 与测试；两者并存；
- `C-xx` 一经发布不改号；新增控件在域内向后续编号；
- 删除/重排控件时，**先改契约与原型、重新评审**，再改代码。

## 2 触发逐条落实（最常被漏的一组）

| 触发 | 实现方式 | 判据 |
|---|---|---|
| `click` | `onClick` | 按下态 ≤100ms 可见 |
| `hover` | CSS `:hover` | 只做增强，**不得作为唯一入口** |
| `focus` | CSS `:focus-visible` + `--focus-ring` | 键盘 Tab 可达，焦点环可见且对比 ≥3:1 |
| `键盘` | `keydown`：Enter/Space 激活、Esc 退出、方向键列表内移动 | 与鼠标行为等价 |
| `长按` | pointer/touch 计时 400–600ms | 触屏才有；必须有非手势替代 |
| `滑动` | touch 位移 ≥8px 判方向 | 起点在按钮/链接/输入框或已选文字上不接管 |
| `输入` | onChange + 防抖 300–400ms | 校验时机与契约一致 |

## 3 移除后五问（第二常漏）

凡是「关闭 / 删除 / 移除 / 撤销 / 取消 / 退出 / 折叠 / 收起」，逐条落实：

| 问 | 本项目口径 |
|---|---|
| 撤销窗口 | 契约写了有就做（给时长）；写「不可恢复」的就不做撤销，但必须有二次确认 |
| 焦点去向 | 关闭弹层/抽屉后焦点回**触发元素**；列表项删除后焦点移到**前一项** |
| 滚动位置 | 抽屉关闭保持原位；列表操作后保持原位（除非契约明写滚到顶部） |
| 计数联动 | 选中数、总数、徽标数、分页数同步；书架「继续阅读」卡随之更新 |
| 列表归属 | 被操作项若不再满足当前筛选，**移出并说明**，不要留在原地装作还在 |

## 4 破坏性操作的确认口径

**只有「不可撤销 **且** 代价高」才加二次确认**，其余用撤销条：

| 操作 | 处置 |
|---|---|
| 删书 / 删章 / 删卷 / 删标签 / 批量删除 | 二次确认，**弹窗写明后果与对象名**（删书要求抄书名） |
| 批量改标签（替换旧标签） | **不加确认**，但结果里给「成功 n / 失败 n」与逐条重试；旧标签不可恢复要写在提示里 |
| 批量改作者 / 改连载状态 | 不加确认，给成功/失败计数 |
| 封面移除 | **即时生效**，不加确认（代价低，可重传） |
| 删书签 | 不做确认；误删需重新添加，提示里写明 |
| 取消导入任务 | 二次确认（任务已产出的数据不丢） |

## 5 演示件隔离（发布构建里必须搜不到）

原型里的 `data-od-id="demo-only:*"` 装置（切状态 / 切断点 / 切页 / 填充数据）**一律不进产品**：

```bash
# 交付前自检，期望输出 0
grep -rc 'demo-only' web/dist/assets/*.js 2>/dev/null | grep -v ':0' || echo 'clean'
```

要保留的调试能力走两层闸：构建层不产出 + 运行层默认关（不显眼手势显式解锁）。

## 6 保真对账（交付必跑）

```bash
# 逐锚点数值对表：缺块 / 字号 / 圆角 / 背景色 / 文字色 / 点击区 <44px 都会被抓
odops spec interaction/<域>/02-prototype.html --out /tmp/spec-<域>.json --yes
odops parity /tmp/spec-<域>.json http://127.0.0.1:8080/<页面> --tol 3 --json
```

**过线**：`parity` 退出 0（P0=0）**且** `counts.total` == spec 的锚点数——比全了才算过。
比不了的页面（要登录 / 依赖异步接口 / 分页过滤）先做**固定数据夹具**让页面停在契约写过的状态，再比；
夹具对不齐就回报「parity 未覆盖 + 原因」，**不写「已按设计实现」**。

对不上按三分法归类，**不要一律改实现**：

| 类别 | 含义 | 处理 |
|---|---|---|
| A 翻译损耗 | 换栈导致（字体度量、行高取整） | 容差内放过，超差报备 |
| B 设计水准 | 原型本身不达标 | 回作者改原型，不放宽实现去凑 |
| C 原型没画 | 需求存在但原型没覆盖 | 回作者补契约与原型，**不自己补** |

| 项 | 判据 |
