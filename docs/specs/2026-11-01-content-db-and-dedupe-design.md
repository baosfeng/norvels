# 正文独立库 + 内容去重 + 版本择优 + AI 审核（设计定稿）

- 状态：已定案（用户 2026-11-01 确认方向：正文独立库、去重先做章级、AI 只走云端、替换需人工确认）
- 关联：[architecture](../architecture.md)、[ADR-0007](../adr/0007-codebook-compressed-content.md)

## 目标

1. 正文从主库拆出成独立 SQLite 文件，元数据/用户/推荐留在主库；
2. 导入前做内容级去重，识别「纯重复」「疑似相关」「更好的版本」三类；
3. 用可解释的质量分对比新旧版本，给出升级建议；
4. 云端 LLM 只做差异段落的语义裁决，异步、可关闭、只作建议。

## 1. 两库布局

| 文件 | 内容 | 体量（生产） |
|---|---|---|
| `data/norvels.db` | books/volumes/chapters/用户/标签/进度/推荐 | 几十 MB |
| `data/norvels-content.db` | `chapter_blocks` + 指纹表 + 审核表 | ~27 GB |

- `chapters.block_id` 变成跨库弱引用，不再有外键。
- 打开方式：`store.Open(ctx, path)` 依据主库路径推导正文库同目录兄弟文件，可用 `NORVELS_CONTENT_DB` 覆盖。

## 2. 一致性：顺序补偿 + 后台对账

WAL 下 SQLite 跨库事务不保证原子，因此**不依赖跨库事务**：

1. **写书**：content.db 事务写本书全部块 → 主库事务写 books/volumes/chapters（引用块 id）→ 主库失败则删 content 中该书块（best-effort）。
2. **删书**：主库事务删章节等 → 提交后删 content 的块；失败留孤儿。
3. **对账**：`ReconcileContent` 扫两库——`book_id` 不存在于主库的块、`chapter.block_id` 指向不存在块的章节，各记一条健康告警；`--fix` 时删除孤儿块。
4. 所有写路径统一收敛到 store 内的单一函数，禁止各处零散实现。

## 3. 迁移 0018

- 逐书流式搬运 `chapter_blocks` → content.db（有界内存），完成后主库 `DROP TABLE chapter_blocks`。
- 幂等：以「主库是否还有 chapter_blocks 表」判定；content 库先 `CREATE TABLE IF NOT EXISTS`。
- 生产 27 GB 约 40–60 分钟，仍用一次性容器预跑 migrate；迁移后 VACUUM。
- 老版本二进制读到无块库时只读不写（块表不存在 → 正文为空并报错，不再静默）。

## 4. 去重判定（章级指纹，P1）

- 指纹：章节正文归一化（去空白/统一标点）后取 64 位哈希，存 `chapter_fingerprints(hash, book_id, bytes)`，放 content.db。
- 判定：新书逐章算哈希，查库内命中（不限于同书），按字节加权命中率：

| 命中率 | 结论 | 行为 |
|---|---|---|
| < 40% | 新书 | 正常导入 |
| 40%–95% | 疑似相关 | 正常导入 + `related_to` 标记 |
| ≥ 95% | 同书 | 进入版本对比 |

- 严格相同文件（`file_sha256` 命中）仍走现有 Skipped。
- 阈值放 `settings`（`dedupe.threshold`，默认 0.95），`force` 一律跳过判定。

## 5. 版本择优（质量分）

| 维度 | 指标 | 方向 |
|---|---|---|
| 乱码 | U+FFFD / 私用区 / 非法字节占比 | 越低越好 |
| 噪声 | 清洗器丢弃的广告/群号/网址行占比 | 越低越好 |
| 结构 | countSanity + 空章率 + 离群章率 | 越高越好 |
| 完整性 | 章数、字数对照旧版本 | 不缺章 |
| 内部重复 | 书内重复段落占比 | 越低越好 |

判定「升级候选」：至少两项显著更优（噪声率降 ≥50% / 乱码率降 ≥80% / 结构分升 ≥0.1），且无一项显著变差
（噪声率升 ≥50% / 乱码率任何上升 / 结构分降 ≥0.1）；任一侧没有质量分走保守路径判重复。
质量指标随 `books` 落列（迁移 0020），导入时同事务写入；解析期没有质量分的书（EPUB / 合集子书）写「未计算」而非 0 分，
历史书用 `norvels backfill-quality` 补算（噪声维度按残留计）。规则表与判定代码见 `internal/store/versionpick.go`。

## 6. AI 审核（云端，异步，可关闭）

- `internal/ai` 叶子包：接口 `Judge(ctx, pair) (Verdict, error)`，DeepSeek 兼容 HTTP 实现，只用标准库。
- 仅在「升级候选」时触发；后台任务，绝不阻塞导入。
- 输入只含差异段落抽样（≤50 段、每段带上下文），不含书名/作者/路径。
- 输出 `{verdict, confidence, reasons[]}`；两次判定不一致或失败 → 降级为规则结论 + 人工确认。
- 结果落 `import_reviews`（迁移 0021，下一阶段），UI 展示「疑似升级版：噪声 3.2%→0.4%、乱码 120→0 处」+ 替换/保留按钮。
- 无 key、超时、报错 → 功能等同不存在，导入流程不受影响。

## 7. 替换语义

- 替换 = 旧书标记 `superseded`（不删块，保留回滚），新书成为当前版本。
- 回滚：一键切回旧版本。
- 任何自动替换都不做，必须人工确认。

## 8. 风险

- 备份从 1 个文件变 2 个，必须成对恢复；`docs/deploy.md` 同步。
- 8 MB 块 + 拆库后单块读 32.5 ms（NAS），阅读页需前端块缓存兜底（已有章节缓存）。
- 章级指纹对「同书微改」不敏感，命中率会低；后续可选 CDC 块级指纹增强。
- AI 判定有幻觉与不可重复性，故只作建议且两次一致性校验。

## 9. 实施顺序

1. 正文拆库（最大改动，先把存储打稳）
2. parser 质量指标（可并行，parser 层独立）
3. 去重指纹 + 导入判定 + 质量分落库
4. AI 审核器 + 审核 UI
