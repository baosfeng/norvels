# AI 选书：导入前的上架判定（2026-11-01）

> 一句话：给一本书的证据，问外部模型「值不值得进这个书库」，判为不入库的按 Skipped 记账，
> 结束打印评审报告。**规则先筛，AI 只做规则做不了的那层判断。**

## 1. 为什么加这一层

现有导入链路已经把三件事做完了：判重（章级指纹）、质量分（乱码率/噪声率/结构分）、
章节门槛。它们都回答「这本书有没有问题」，唯独回答不了「**这本书值不值得占一个书架位**」——
盗版残卷可能在指标上完全正常，拼凑合集也可能结构分很高。

所以这一层不重复算指标，只把指标当作**证据**交给模型，让模型给出可解释的三态结论。

## 2. 三块边界

| 层 | 包 | 职责 | 不认识 |
|---|---|---|---|
| 判定实现 | `internal/ai` | `Curate`：书卡 → 三态结论；复用 Judge 的传输层 | 不认识书库、不认识导入 |
| 端口 | `internal/importer` | `Judge` 函数类型 + 调用时机 + 记账 | 不认识任何 AI 实现 |
| 接线 | `cmd/norvels` | 从解析产物挑证据、三态压二态、成本护栏、报告 | 唯一同时认识两边的文件 |

`internal/importer` 的依赖白名单**没有变化**（仍然只有 model/parser/store/ebook/source），
`internal/ai` 仍然是叶子包（只用标准库）。这是刻意维持的：判定器换成本地模型、换成规则引擎，
都不用动导入链路。

```
扫描 ──► 解析 ──► 章节门槛（免费规则）──► 判重（免费规则）
                        │
                        └─► Judge（可选）──► 写库 / 跳过
                                │
                                └─► 评审记录 ──► 结束打印报告
```

判定排在**章节门槛之后**：被门槛挡掉的书不该花钱去问模型。

## 3. 判定口径

提示词把模型限制在三件事上，且理由必须引用证据：

| 维度 | 问什么 |
|---|---|
| 能不能读 | 正文完整可读？不是乱码、广告页、残缺抓取 |
| 是不是残卷 | 首章像简介、末章一句话中间截断、章节数相对字数明显偏少 |
| 是不是拼凑 | 多本塞进一个文件、正文与书名对不上、同一段反复出现 |

输出契约（严格 JSON，解析失败即 `ErrBadResponse`）：

```json
{"decision":"import|skip|review","score":0,"reasons":["..."],"category":"","tags":[]}
```

- `category` 只能取自**库内已有分类**，编造的分类一律丢弃——否则筛选器上会出现只有一本书的孤岛。
- `score` 越界直接报错而不是截断：那是提示词被改坏或模型跑偏的信号。

## 4. 降级与成本

| 情况 | 行为 | 理由 |
|---|---|---|
| 没有 key | 入口直接报错，不开跑 | 开了开关却没有 key，运行到一半才发现更糟 |
| 判定器返回错误 | **fail-closed**：按不入库记账并留原因 | 书可以再导，错导要人工删 |
| `review`（拿不准） | 同样不入库，理由写「需人工确认」 | 见上 |
| 达到 `--ai-limit` | 之后的书一律按不可用处理 | 上限按**调用次数**计，判定失败也计数，否则反复失败会绕过护栏 |

默认 `--ai-limit 200`：一本本导入时用不到，成批扫目录时是刹车。

## 5. 用法

```bash
export NORVELS_AI_API_KEY=...          # 或指向本地模型：NORVELS_AI_BASE_URL=http://127.0.0.1:11434/v1
./bin/norvels import --dir /books/某本书.txt --ai
./bin/norvels import --dir /books --ai --dry-run   # 只看 AI 怎么说，不写库
```

报告示例：

```
AI 评审：共 3 本（入库 1 / 不入库 2），调用 3 次
  入库    87 分《某书》结构完整，末章收束自然
  跳过    12 分《另一本》末章正文在一句话中间截断
  待确认  55 分《第三本》开头三段都是网址广告
```

## 6. 已知取舍

- **逐本调用**，不批量：一本书一个请求。判断更准、prompt 更短，代价是每本一次往返；
  成批导入时用 `--ai-limit` 刹车。
- **不落库**：评审结论只出现在本次运行的文件终态（`import_job_files.reason`）与报告里。
  要「三个月后回看当初为什么没导」需要建 import_verdicts 表，等真的需要再加。
- **不自动改分类**：模型给的 `category` 目前只进报告，不写库——写库会让「AI 改了我的分类」
  变成一个需要撤销机制的动作。
