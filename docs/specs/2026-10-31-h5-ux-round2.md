# H5 体验修复第二批：候选书分页 · 阅读器底部留白带 · 筛选抽屉分类（2026-10-31）

> 来源：用户实机反馈三条，均经 390×844 实测复现，根因不是猜测。
> 纯前端（web/src），不动后端、不加迁移。

## 1. 用户可见行为

- 书单「添加书籍」：滚到底自动加载下一页，顶部常显「已显示 M / 共 N 本」，加载完显示「已全部显示（共 N 本）」。
- H5 阅读：屏幕底部不再有横贯全屏的白条与细线压着正文；恢复提示变成只包住文字的胶囊，3 秒自动消失。
- H5 书架筛选：分类一眼看全（chips 铺开，选了大分类紧跟小分类），作者候选整块去掉；深链带 authorId 时留一个可清除的「作者：名字 ×」。

## 2. 契约

### 2.1 候选书分页

- 一页 20 本；滚动容器距底 ≤80px 触发下一页，重复触发由 loading / hasMore 守卫挡掉。
- 顶部「已显示 M / 共 N 本」以接口 total 为准；无匹配时 0 / 0。
- 关键词变化 → 整份重置回第 1 页；已勾选的 id 集合保留（换词不丢）。
- 追加失败：已加载的仍可勾，底部行内提示 + 重试（只重发失败页）。
- 后端返回空页时把 total 收敛到已加载数，避免反复取空页。

### 2.2 阅读器底部留白带（H5 ≤768px）

- `.reader-shell` padding-bottom：收起 96px、`.is-controls` 120px（均含 safe-area）。
- 正文滚动区 `padding-bottom: 16px`；留白带本体在外壳上——只给滚动容器加 padding 时，滚到章中文字仍会铺到视口底边、压在浮层下面。
- `.reader-scroll-track` 贴视口底（bottom: safe-area）；`.reader-scroll-chip` 在细条上方 7px（bottom 10px）。
- `.restore-hint`：`width: fit-content` 胶囊，窄屏 bottom 10px；「知道了」按钮 ≥44px。
- 自动滚动浮条 `.reader-autoscroll` 同样收进带内（bottom 10px，覆盖 prototype.css 的旧口径 78px）。
- 恢复胶囊 / 自动滚动浮条在场时，本章浮标让位（`chipSuppressed`）——两个浮层不叠字。
- PC（≥769px）不变：外壳 padding 0、正文底 64px、浮标 12px。

### 2.3 筛选抽屉的分类与作者

- 分类不用原生 select：大分类 chips 换行全量（含「全部」与计数），选中后紧跟小分类 chips（左侧竖线缩进）；无细分显示「该分类暂无细分」。
- 作者候选块在 H5 移除；authorId 非空时渲染一行「作者：名字 ×」可清除。
- PC 工具栏与 FilterHints 不变。

## 3. 验收（390×844 实测，agent-browser）

| 项 | 数据 |
|---|---|
| 候选书滚动 | 首屏 20 本 → 滚到底 40 本；顶部「已显示 40 / 共 838 本」 |
| 阅读器收起态 | 正文可视底 748，恢复胶囊顶 772（gap 24），细条 841，胶囊宽 248（非全宽） |
| 阅读器展开态 | 正文可视底 724，底栏顶 737（gap 13），外壳留白 120px |
| 320×640 | 末行 528.8 / 浮层顶 568（gap 39.2） |
| PC 1280 | 外壳 padding 0、正文底 64px、浮标 12px（与改前一致） |
| 筛选抽屉 | DOM 内 select 0 个；分区 5 个（排序 / 阅读状态 / 评分 / 分类 / 书单）；分类 chips = 全部 + 节点数 |

## 4. 工程化决定

| 决定 | 依据 |
|---|---|
| 候选书滚动追加，不一次拉全库 | 一次拉 838 本既慢又白占内存；读者多半只看前几十本 |
| 留白带做在外壳而不是滚动容器 | 只有裁切滚动区，才能保证任何滚动位置末行都在浮层之上 |
| 底部留白只在一个文件里定 | 原先 globals.css 与 ix-reader.css 各有一套数（56 / 96），并存就是迟早改一处漏一处 |
| 作者筛选移除但保留清除入口 | 深链带 authorId 时若没有出口，H5 上无法取消该筛选 |
| 分类 chips 全量铺开而非横滑 | 分类是「先定大类」的入口，横滑等于把它藏起来 |
