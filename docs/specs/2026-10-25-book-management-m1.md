# 书籍管理 M1：独立后台 · 章节结构编辑 · 封面上传（2026-10-25）

> 来源：用户评审 `.open-design/09-admin.html` 原型后的追加要求——「要一个单独的管理页，能改章节；
> 一章几万字没识别到的要能拆成多章」。本批是 M1，M0（管理页骨架 + 元信息编辑）同批完成。
> 边界：不做正文编辑、不做卷重排/卷增删、不做章节合并、不做批量删除章节（都是 M2）。

## 1. 用户可见行为

- 侧栏「书籍管理」进独立后台（PC 专属）：列表可搜索、按连载状态/标签筛选、分页、多选批量改。
- 单书页左栏封面 + 元信息 + 危险区，右栏按卷分组的章节表；改元信息要保存，改章节即时生效。
- **章节行三个动作**：改标题、拆分、删除。
- **拆分**：一章吞掉整卷正文时，按段落边界切成多章。段落之间点「从这里拆开」（可多点、可取消），
  也可填「每章目标字数」自动布点；右侧实时给出拆成几章与各章字数。正文一个字节不改。
- **删除章节**：二次确认写明书名 + 章节名；删完后面章节序号自动补上。
- **封面上传 / 删除**：JPEG/PNG/WebP/GIF，≤2 MiB；删掉回退成书名首字占位。
- 阅读详情页只剩只读信息 + PC 上的「管理这本书」入口，编辑与删除控件全部移除。

## 2. 契约

### 2.1 API（正文见 [api-books.md](../api/api-books.md)）

| 端点 | 契约 |
|---|---|
| `PATCH /api/books/{id}/chapters/{cid}` | body `{"title"}`；204；空/超 200 字 400；不存在 404 |
| `POST /api/books/{id}/chapters/{cid}/split` | body `{"cutAfter":[0,11]}`；200 `{"chapters":N}`；切点乱序/越界/切出空章 400 带原因 |
| `DELETE /api/books/{id}/chapters/{cid}` | 204；后续 `idx` 自动前移；重复删 404 |
| `PUT /api/books/{id}/cover` | multipart 字段 `cover`；204；非图片/超 2 MiB 400；体 >3 MiB 413 |
| `DELETE /api/books/{id}/cover` | 204 幂等；`has_cover` 置 0 并刷新 `updated_at` |
| `GET /api/books?serialStatus=` | 新增筛选：`ongoing|completed|none`（none = 未知）；其它值 400 |

### 2.2 存储不变量（store 层）

- 正文按 span 存（`chapters.block_id + block_off + block_len`）。**拆分只是把一个 span 切成几段**：
  不重压、不搬数据，几万字的章也是毫秒级；拆出来的章指向同一个压缩块的不同区间。
- `cutAfter` 是 0 起的**段落下标**（「在这一段之后切开」），严格递增、落在 `0 ~ 段落数-2`；
  每段必须有字（空行之间不算切点）。
- 新章标题 `原标题（i/N）`；`idx` 紧跟原章、其后各章整体 `+N-1`；原章 id 保留（阅读进度/书签靠它）。
- 三处计数同事务维护：`books.chapter_count`/`word_count`（按各段 `countWords` 实际重算取差值）、
  `store_metrics.chapter_word_sum`；删除导致正文块无人引用时整块回收并冲减 `text_bytes`/`text_bytes_raw`。
- 段落口径全站一致：正文按 `\n` 切行，行尾换行留在前一段（阅读器 `paraIndex`、书签、拆章同一套）。

### 2.3 前端

- `/admin`（列表）与 `/admin/books/:bookId`（单书）都包在 `TierRoute` 里：H5 下不渲染，直接跳首页。
- 元信息是**草稿**（改动攒在吸底操作条、可放弃、离开拦截）；章节与封面是**即时生效**，改完立刻 reload。
- 批量操作是前端逐本下发既有 PATCH/DELETE（本地库几十本可接受），失败项单独列出可重试。
- 拆分面板只在段落边界切；预览字数用 `lib/splitPlan.ts`，与后端 `countWords` 同口径。

## 3. 工程化决定

| 能力 | 决定 | 依据 |
|---|---|---|
| 拆分只切 span | 做 | 解压重压一本书是分钟级且有损坏风险；切区间是毫秒级且不改一个字节 |
| 章节结构即时生效 | 做 | 与元信息草稿混在一次保存，最容易把用户删掉的章又存回去 |
| 只在段落边界切 | 做 | 按任意字符切会把一句话劈两半，这种坏数据修不回来 |
| 不提供合并 | 省 | 拆错了用「改标题 + 删多余章」恢复；合并要先解决书签/进度归属 |
| 批量走前端扇出 | 做 | 不新增「部分成功」的事务语义；失败项可重试 |
| 正文编辑 / 卷重排 / 批量删章 | 省（M2） | 都要改块布局或重排语义，先让拆分跑起来 |

## 4. 验收

- `make gate` 11 项全绿，覆盖率不低于基线。
- 拆分：一章 4 段 `cutAfter=[1]` → 2 章，拼回来的正文与原章完全一致，字数之和按 `countWords` 守恒；
  新章在同一卷、`idx` 连续；`cutAfter` 乱序/越界/切空行 → 400 且不改库。
- 删除：删中间那章 → 目录少一章、序号补上、首尾章 id 不变且正文可读；删掉唯一一章 → 正文块回收、`text_bytes` 下降。
- 标题：去空白后落库；空标题/超 200 字 400；不存在 404；书 `updated_at` 刷新。
- 封面：上传后 `GET /cover` 字节一致、`hasCover=true`；删除后 404 且 `hasCover=false`；再删仍 204。
- 列表筛选：`serialStatus=none|ongoing|completed` 各命中对应数量；非法值 400。
- 前端 261 例全绿（新加 `splitPlan`/`metaDraft` 纯函数、拆分面板、列表、单书页四组）。
