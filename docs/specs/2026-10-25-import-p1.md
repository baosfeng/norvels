# 导入 P1：ZIP 批量 · 合集拆分 · 追更增量 · 卷层级 · 多作者（2026-10-25）

> 前置：`docs/specs/2026-10-25-import-formats.md`（上传 + EPUB + 封面/元数据）已交付。
> 本文件只写增量契约；与前置冲突处以本文件为准。

## 1. 用户可见行为

- 目录导入与浏览器上传都接受 `.zip`：包内 `.txt`/`.epub` 逐条导入，结果条目名为 `包名.zip:内部路径`。
- 一章号反复重置的多书合集自动拆成多本；书名取段内书名标记，取不到记 `原标题（第 N 段）` 并给 warning。
- 同一本书再次导入可选**追更**：只追加新章节，已有章节 id 不变、阅读进度保留；做不到时明确报错而不是覆盖。
- EPUB 的目录层级映射成卷（`nav.xhtml` 优先、`toc.ncx` 兜底）；没有层级则平铺。
- 多作者入库与可编辑；详情页可把简介/系列清空。

## 2. 契约

### 2.1 迁移 0009（只加表，不删列，无需 VACUUM）

```sql
CREATE TABLE books_authors(
  book_id INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  author_id INTEGER NOT NULL REFERENCES authors(id),
  position INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY(book_id, author_id));
CREATE INDEX idx_books_authors_author ON books_authors(author_id);
```

- `books.author_id` 保留 = `position 0` 的主作者，`authors` 聚合列的统计口径不变。
- 存量书不回填 `books_authors`（读取时主作者兜底）。

### 2.2 model

```go
type ParsedBook struct {
    // 既有字段不变
    Author  string    // 主作者，兼容旧路径
    Authors []string  // 有序作者；为空时视作 []string{Author}
    SplitOf string    // 合集拆分来源（原 SourcePath），未拆分为空
}
```

### 2.3 store

- `SaveOptions{Force bool; Update bool}`。
- `SaveBook` 在 `Update=true` 时：先按 `source_path` → `file_sha256` → `title+author` 顺序找已有书；
  - 未命中 → 按普通导入新建；
  - 命中且新章节序列以旧序列为前缀（逐章比 `title`）→ 追加尾部章节，更新 `chapter_count`/`word_count`，已有章节 id 与 `reading_progress` 不动；
  - 否则返回 `ErrNotAppendable`（API 映射 409 `not_appendable`，CLI 非零退出）。
- 多作者：写 `books_authors`（按 `Authors` 顺序写 `position`），`author_id` 仍写主作者。
- 新增 `FindByTitleAuthor(ctx, title, author) (int64, bool, error)`。

### 2.4 importer

- `FormatZIP`；解包后每个条目复用现有 parse→save 流程。上限：条目 ≤1000、解压总量 ≤512 MiB、单条目 ≤64 MiB，拒绝绝对路径与 `..` 穿越；不支持条目逐条记 rejected / `import_errors`。
- 合集拆分：`parser.SplitSegments(chapters []ParsedChapter) []Segment`（`Segment{Title string; Chapters []ParsedChapter}`）无拆分点时返回单段。importer 对 `MultiBook` 书按段产出多个 `ParsedBook`，`SplitOf` 填原 `SourcePath`。
- 拆分后的唯一性：第 1 段沿用原 `source_path`/`file_sha256`；第 N 段（N≥2）`source_path = 原路径 + "#N"`、`file_sha256 = sha256 + ":N"`，重导能命中同一段。
- 追更匹配顺序与 `SaveBook` 一致，由 store 提供，importer 只透传 `Update`。

### 2.5 API

| 变更 | 契约 |
|---|---|
| `GET /api/books/{id}` | 新增 `authors: string[]`（有序）；`author` 保留为主作者 |
| `PATCH /api/books/{id}` | 新增 `authors`（`string[]`，全量替换，空数组 400）；`intro`/`series` 传 `""` 即清空；`seriesIndex` 传 `0` 即清空 |
| `POST /api/import` / `/api/import/upload` | 新增 `update`（布尔，默认 false） |
| 上传 `accepted` | `name` 可能含 `包名.zip:内部路径`；`format` 取包内真实格式 |
| 错误码 | 新增 `invalid_zip`、`zip_too_large`、`empty_zip`、`not_appendable` |

### 2.6 前端

- `BookMetaPatch` 允许空串与 0；`buildPatch` 以「改过即下发」为准，不再按真值过滤。
- 作者字段多值编辑（逗号/顿号分隔，去重去空）。
- 上传预检放行 `.zip` 并提示包内将逐条导入；结果表展示包内条目。

## 3. 工程化决定

| 能力 | 决定 | 程度 | 依据 |
|---|---|---|---|
| ZIP 输入校验 | 做 | 条目数 / 总量 / 单条目 / 路径穿越四道闸 | 跨信任边界的压缩炸弹入口 |
| 追更幂等 | 做 | 前缀匹配才追加，否则拒绝 | 静默覆盖会毁阅读进度 |
| 兼容 | 做 | 无 `books_authors` 行时按主作者兜底 | 存量库不回填 |
| 日志 | 做 | 拆分/追更/zip 拒绝原因进既有 `import_errors` | 沿用现状口径 |

## 4. 验收

- `make gate` 9 项全绿，覆盖率不低于基线（总 77.9 / store 80.2 / parser 87.8 / importer 85.1 / api 80.1，只升不降）。
- 目录含 `a.txt`+`pkg.zip(含 b.txt、c.pdf)` → b 入库、c 进 rejected，a 不受影响。
- 合集文件（两段章号从 1 重置）→ 产出 2 本书，各自章节数正确，`SplitOf` 指向原文件。
- 追更：先导 10 章，再导 15 章同书 → 新 5 章追加、原 10 章 id 不变、阅读进度仍能打开；倒序/改名的 15 章 → 409 `not_appendable`。
- EPUB 目录带 `卷/章` 两级 → `GET /api/books/{id}/chapters` 返回卷分组；无 TOC 的书平铺。
- 多作者 EPUB（两个 `dc:creator`）→ `authors` 有 2 项；`PATCH authors` 全量替换生效，`/api/authors` 统计口径不变。
- 详情页把简介清空 → `GET` 返回空串；系列同理；`seriesIndex` 重置为 0。
- 回归：现有目录导入、上传 txt/epub、`--force`、单任务互斥、封面接口行为不变。
