# 书籍管理 M1-C1：章节正文编辑（2026-10-25）

> 来源：M1/M2 边界清单里挂着的「不做正文编辑」（见 [m1](2026-10-25-book-management-m1.md)、
> [m2](2026-10-25-book-management-m2.md) §3）。本批只补**服务端**能力与契约：整章替换正文。
> 边界：纯文本、不做富文本、不做版本历史、不做并发冲突检测、不动迁移、不改块布局策略。

## 1. 用户可见行为

- **正文抽屉**：目录页 / 阅读页对单章点「编辑」拉出侧边抽屉，里面是该章正文的纯文本 `textarea`
  （等宽字体、保留空行）；保存 = 一次 `PUT`，成功后抽屉关闭并重拉章节，界面显示服务端算出的字数。
- **实时字数**：抽屉里随输入更新「N 字」（与目录列同一口径：CJK 逐字、空白与标点不计）；
  上限提示写「1 MiB（约 36 万汉字）」，接近上限时提示变红但**不拦输入**（判定留给服务端）。
- **未保存拦截**：有改动时关闭（点遮罩 / Esc / 切章）要二次确认「放弃未保存的修改？」；
  保存中禁用关闭；保存失败时抽屉保持打开、错误就地显示（不丢用户输入）。
- **书签偏移提示**：正文被替换后，本章原有书签的 `paraIndex`（段落下标）可能落到别的位置——
  保存成功提示「本章有 N 个书签，位置可能已变」，并给「查看书签」入口（不做自动迁移）。
- 失败一律**一个字节都不改**：正文、字数、统计、块全部停在编辑前状态。

## 2. 端点契约

正文见 [api-books.md](../api/api-books.md)「PUT /api/books/{id}/chapters/{chapterId}/content」。

| 项 | 值 |
|---|---|
| 请求 | `PUT /api/books/{id}/chapters/{cid}/content`，body `{"content":"…"}`，`Content-Type: application/json` |
| 成功 | **204** 无响应体（前端重拉 `GET /api/books/{id}/chapters/{cid}` 拿新正文与 `wordCount`） |
| 空正文 | 去空白后为空 → 400 `invalid_param`「章节正文不能为空（去空白后为空）」 |
| 超限 | 正文 > **1 MiB**（1,048,576 字节，UTF-8 编码后）→ 400 `invalid_param`，message 带实际上限 |
| 不存在 | 章节不存在 / 不属于该书 / 书不存在 → 404 `not_found` |
| 路径与体 | `id`/`cid` 非数字 → 400 `invalid_id`；非法 JSON / 多值 / 缺 `content` → 400 `invalid_param` |

- 请求体上限 8 MiB（JSON 转义后可能膨胀），正文 1 MiB 由 store 判：超限要得到「上限是多少」，
  而不是被体积截成「请求体不是合法 JSON」。
- 幂等：同一份正文重复 PUT 结果一致；但没有版本号——见 §4。
- 响应不回正文：前端本来就要重拉，回一份是两份真相。
- 正文按**字节原样**落库（不 trim、不做换行归一）：首尾空行是用户的排版，服务端不替他删。

## 3. store 不变量

- **整章替换写新块**：正文按 span 存（`chapters.block_id/off/len`），块是 zstd 压缩的不可变字节；
  块内改动要挪字节并重算**同块所有章节**的偏移。因此替换一律「压新块 → 改本章 span」，
  新块只装这一章（`block_off=0`），同块其他章节一个偏移都不动。
- **词数重算**：新 `word_count = countWords(新正文)`（CJK 逐字、空白与标点不计）；
  `books.word_count` 与 `store_metrics.chapter_word_sum` 都按「新算 − 存量」的**增量**维护
  （与删除 / 合并同口径），不重算全书——一次编辑不该改掉别的章的历史值。
- **旧块回收**：改完 span 后旧块可能已无人引用，此时整块删除并冲减 `text_bytes`（压缩字节）与
  `text_bytes_raw`（原文逻辑字节）；仍被同块其他章引用则两项都不减（那块数据还在用）。
  不回收的后果是：读者把正文改小，`/api/stats` 的正文体积只涨不降。
- **单事务**：写块、改 span、三处计数、`books.updated_at` 刷新、旧块回收在同一事务，
  任一步失败整体回滚——不接受「正文换了、计数没动」的半成品。
- **位置不动**：`chapters.id` / `idx` / `volume_id` / `title` 不变（`reading_progress` 与 `bookmarks`
  按 chapter id 指过来，`idx` 是目录顺序）；块的 `first_idx/last_idx` 按新块校正，仅用于损坏文案。

## 4. 工程化决定

| 能力 | 决定 | 依据 |
|---|---|---|
| 纯文本，不做富文本 | 强制 | 存的是 span 切片；富文本要引入标记语法与渲染器，读者改的是错字与断句，不是排版 |
| 不做版本历史 | 省 | 没人提过「回退上一版」；留历史要另存全文副本，与「正文只占压缩字节」的成本模型冲突，真要做时单独立表 |
| 不做并发冲突检测（无 version / ETag） | 省 | 本地单用户：同一章不会有第二个写者；加版本号只会把「保存失败」变成日常噪音 |
| 后写覆盖先写 | 强制语义 | 与「不做冲突检测」配套的唯一可预期行为：最后一次保存生效，不合并、不拒绝 |
| 一次写入原子 | 强制 | 部分成功会让正文与字数对不上（读者看到错的目录字数），且没有自愈入口 |
| 限额 1 MiB | 强制 | 块以 1 MB 为目标；正文来自 HTTP 请求体，跨信任边界必须封顶，否则一次 PUT 能把库撑大 |
| 一章一块 | 强制 | 整章替换只碰这一章：块内偏移恒为 0，不必动同块其他章；代价是产生小块，可接受 |
| 书签只提示不迁移 | 省 | 整段替换后段落偏移无法可靠映射；自动迁移等于替读者猜意图 |
| 迁移 / schema 变更 | 不做 | `word_count` 列早已存在，替换只写值 |

## 5. 验收

- `go test ./internal/store/ ./internal/api/ -count=1` 全绿；`go build ./...`、`go vet`、`gofmt -l` 干净。
- 覆盖：替换后 GET 逐字节一致、两处聚合计数同步、章 id 与 idx 不变、独占块回收后 `text_bytes` 下降、
  空正文 400、超 1 MiB 400、`cid` 不属于本书 404。
