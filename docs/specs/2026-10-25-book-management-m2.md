# 书籍管理 M2：章节批量删除 · 合并 · 重编号（2026-10-25）

> 来源：M1 边界清单里挂着的三项（见 [m1](2026-10-25-book-management-m1.md) §3「不提供合并 / 批量删章」），
> 本批补齐**服务端能力**：勾选多章一次删、把拆错的相邻章并回去、按序号重写标题。
> 边界：不做卷增删与卷重排、不做正文编辑、不改块布局策略、不动迁移。

## 1. 用户可见行为

- 章节表多选后出现「批量删除」：二次确认写明书名 + 勾选章数 + 前几章标题；删完勾选清空、目录序号补上。
- 选中的章节**同卷且连续**（≥2 章）时才出现「合并」：并成一章，标题取首章原标题、正文顺序接上，
  成功提示「已合并，全书还剩 N 章」。
- 「重编号」两个入口：全书（页面级按钮）与单卷（卷标题菜单）；提示「已重编号 N 章」。
- 三个动作都即时生效（不进元信息草稿）；任何失败**一个字节都不改**，错误原因就地展示
  （合并被拒时给出「跨卷」「不连续」这类可照着改选的原因）。

## 2. 契约

### 2.1 API（正文见 [api-books.md](../api/api-books.md)）

| 端点 | body | 成功 | 错误 |
|---|---|---|---|
| `POST /api/books/{id}/chapters/batch-delete` | `{"chapterIds":[10,11]}` | 204 | 空数组 / 重复 / 非正 → 400 `invalid_param`；任一章不属于本书 → 404 `not_found` |
| `POST /api/books/{id}/chapters/merge` | `{"chapterIds":[10,11]}` | 200 `{"chapters":N}`（合并后全书章数） | 少于 2 章 / 空 → 400；`store.ErrNotMergeable` → **409 `not_mergeable`**，`message` 原样带原因；不属于本书 / 不存在 → 404 |
| `POST /api/books/{id}/chapters/renumber` | `{"scope":"book"}` 或 `{"scope":"volume","volumeId":7}` | 200 `{"renamed":N}` | scope 非法 / 缺 volumeId → 400；卷不属本书 → 404 |

- 入参解析 fail-closed：多余字段忽略、类型不符 400、体积上限沿用现有限制；一次请求要么全成要么全不动。
- `merge` 的 N 是**全书章数**（合并结果恒为 1 章，返回「这次并了几章」没有信息量）；
  `renumber` 的 N 是**范围内章数**（标题本来就对的章不写库，因此是范围而非实际行更新数）。
- `scope=book` 时忽略 `volumeId`：多余字段不参与判定，前端不必先清空它。

### 2.2 存储不变量（store 层，已交付，本批只消费）

- **合并保留首章 id**：`reading_progress` 与 `bookmarks` 都按 chapter id 指过来，保住目录里的第一章
  就是保住读者的位置；被并掉的章节行删除，首章标题与卷归属不变。
- **span 直拼 vs 新建块**：各章本就在同一块里连续时（拆分留下的典型形态）只把首章 span 拉长到覆盖整段，
  零拷贝、不解压不重压、不动 `text_bytes`；跨块才新建一个块写入合并后的正文。
- **idx 重排**：三个动作结束时都把该书 `idx` 重排成 0 起连续（顺带修掉存量空洞）；单卷重编号**不动 idx**。
- **三处计数同事务**：`books.chapter_count`/`word_count`、`store_metrics`（`chapter_word_sum` /
  `text_bytes` / `text_bytes_raw`）、`books.updated_at` 在同一个事务里维护。合并字数**净变化 0**
  （各章存量 `word_count` 之和落到首章），删除按存量 `word_count` 扣减。
- **块回收**：不再被任何章节引用的 `chapter_blocks` 行整块删除并冲减字节计数，文件不虚空。
- **重编号只改 title**：不动 `block_id`/`block_off`/`block_len`、不动 `idx`（「第 N 章」的 N 就是
  `idx+1`），几万章也是毫秒级；单卷范围下 N 仍是**全书序号**，否则目录里会出现两个「第 3 章」。

## 3. 工程化决定

| 能力 | 决定 | 依据 |
|---|---|---|
| 合并只允许同卷连续 | 强制 | 跨卷合并会抹平卷结构；不连续合并等于偷偷搬正文，读者按目录找不回章节 |
| 合并冲突用 409 而非 400 | 做 | 「这份目录结构上合不了」不等于「参数写错了」：重发改好的请求也没用，得重选章节；400 会让前端当表单错误整块标红 |
| 冲突原因原样带回 | 做 | 用户唯一能做的动作是照着原因重选（跨卷 / 不连续），笼统的「无效参数」帮不上忙 |
| 重编号只改 title | 强制 | 序号由 `idx` 决定；改 idx 会让书签与阅读进度错位，且要重排块 |
| 批量删除不新增语义 | 不新增 | 与单章删除同一套口径（三处计数 + 块回收 + idx 重排），差别只是同一事务里一次做完 |
| 不做「部分成功」 | 强制 | 目录留半成品时用户看到的章数与勾选数对不上，且没有自愈入口 |
| 批量走服务端单事务 | 做 | 前端逐章扇出会在「某章已不存在」处停下，留下半成品目录 |
| 卷增删 / 卷重排 / 正文编辑 | 省 | 要改块布局或出版语义，与本批目标无关 |

## 4. 验收

- `go test ./internal/api/ ./internal/store/` 全绿；`go build ./...`、`go vet ./internal/api/`、`gofmt -l` 干净。
- 三端点各覆盖：一条成功 + 一条 400 + 合并的 409（跨卷与不连续各一条）+ 一条 404，并断言失败时目录未变。
- 批量删除：删 3 章 → 204、序号连续补上、剩余章 id 不变、正文块与计数同步。
- 合并：同卷两章（请求里 id 顺序故意打乱）→ 200、首章 id 与标题保留、正文按目录顺序拼接、章数净减 1。
- 重编号：全书 4 章 → `renamed=4`、标题为「第 1 章 起」…；单卷 → 只改该卷、章号仍是全书序号。
- 门禁 4/5 自查：单函数 ≤70 行、单文件 ≤400 行、圈复杂度 ≤10，不新增豁免。
- 两个文档（本文件与 api-books.md）各 ≤120 行。
