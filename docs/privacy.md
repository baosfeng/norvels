# 隐私与仓库卫生

这个仓库的用途是**工具本身**，不含任何私人书库内容。为了避免把不该公开的东西带进 git 历史，
所有对外可见的示例、文档、原型数据都做了脱敏，并配了一个提交前扫描脚本。

## 1. 边界：什么进仓库，什么不进

| 内容 | 是否入库 | 说明 |
|---|---|---|
| 源码（Go / 前端 / 脚本 / 部署） | ✅ | 主体 |
| 文档（架构 / API / 部署 / 调研） | ✅ | 已脱敏 |
| 原型 HTML + 对比页 | ✅ | 用虚构书目数据 |
| 原型截图 `shots/` | ❌ | 由工具本地生成，重跑即可；忽略可避免把历史截图（可能含真实书名）带进版本库 |
| Open Design 模版种子 `seed/` | ❌ | 第三方资产，用 `odops template-use` 重新拉取 |
| 数据库文件 `*.db` / WAL | ❌ | 内含全文正文 |
| 原始 txt 语料 | ❌ | 从不入库，也不进构建上下文 |
| 本机黑名单 `.privacy-denylist.txt` | ❌ | 里面正是真实书名/作者，只在本地维护 |

`.gitignore` 覆盖上述所有项；`.dockerignore` 另外把语料与数据目录挡在镜像构建上下文之外。

## 2. 脱敏规则（写文档/原型时照这个来）

| 类型 | 处理方式 | 示例 |
|---|---|---|
| 本机绝对路径 | 用占位符 | `/Users/⟨用户名⟩/Documents/…` → `/path/to/txt` |
| 内网地址 / 带 IP 的目录名 | 不出现 | 一律替换为 `/path/to/txt` |
| 真实书名 / 作者名 | 换虚构名 | 见原型数据（长夜书简 / 青川剑录 / 沈砚 …） |
| 真实站点域名 / 群号 | 换成 `example.com` / 顺序号 | `example-site.com`、`100000001` |
| 真实地名 | 换成虚构地名 | 统一用「临川市」 |

例外：**书源广告噪声词**（`internal/parser/normalize.go` 的清洗词典）是解析器的功能性输入，
必须保留原样才能命中真实语料；这类词只出现在代码与清洗规则说明里，不指向具体馆藏。

## 3. 提交前自检

```bash
scripts/privacy-scan.sh            # 扫描暂存区（先 git add）
scripts/privacy-scan.sh --all      # 扫描工作区全部文件
make privacy                       # 等价的 Makefile 目标
```

扫描分层：

1. **通用规则**：本机绝对路径（`/Users/`、`/home/`）、疑似 IP、真实邮箱、私钥、GitHub / AWS / API 令牌。
   回环地址（`127.0.0.1`、`0.0.0.0`、`localhost`）自动放行——它们是正常的本地开发地址。
2. **项目黑名单** `.privacy-denylist.txt`：一行一个词，登记真实书名 / 作者 / 站点 / 内网地址；文件本身不入库。
3. **跳过**：二进制、图片、数据库、`node_modules`、`dist`、`go.sum`。

命中时脚本以退出码 1 结束并列出 `文件:行号:摘录`；干净时输出 `✅ 未发现敏感内容`。

### 反向验证（脚本自身可信度）

把一条本机绝对路径、一个公网 IP、一个局域网 IP 与一个真实书名写进临时仓库再扫描，
脚本应报 4 类命中并退出 1；清掉后应报干净。改动扫描规则后按这个方法验一次。

## 4. 首次提交做了什么

1. 全仓替换：绝对路径 → `/path/to/txt`；真实书名/作者 → 虚构名；站点域名 → `example-*`；真实地名 → 「临川市」。
2. `docs/data-profile.md` 的广告样例行换成示例群号/示例站点（保留结构，便于说明清洗策略）。
3. 测试夹具里的真实作者名换成「示例作者」。
4. `.gitignore` 增加 `shots/`、`seed/`、`.privacy-denylist.txt`。
5. 新增 `scripts/privacy-scan.sh` + 本文件 + `make privacy`。

## 5. 已经进过历史的内容怎么处理

若某次提交确实带进了不该有的内容，**不要只在下一次提交里删掉**（文件仍在历史中）：

```bash
# 仅本地仓库、尚未推送时
git rebase -i <可疑提交之前>      # 改写该提交
# 或对整个历史做替换
git filter-repo --replace-text replacements.txt
```

已推送过就需要强推并让协作者重新克隆；因此**推送前先跑 `make privacy`** 比事后清理便宜得多。
