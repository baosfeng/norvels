# 正文压缩方案调研报告

> 评估报告（未定案）。目标：在不改「详情页按需解压」架构的前提下，确定内容压缩还能往哪里走。
> 数据口径：真实库 838 本 / 4.87 GB 正文；样本实验 12 本 / 74.5 MB；全库验证 200 本 / 1.23 GB。
> 现行方案见 [ADR-0003](adr/0003-block-compressed-content.md)，历史压缩口径见 [data-profile](data-profile.md) §10.3。

## 结论

1. **实时纯 Go 的终局是全局码本 + 整本 zstd，26.8%（全库 200 本实测）**，已贴着 1 阶上下文的
   理论下限（26.3%），比现状 34.7% 省 7.9 个百分点（全库约 380 MB）。
2. **再低必须换模型，不是换编码**：PPMd 22.5%、CM 20.4% 都要外部 CLI 且解压秒级；
   10% 只有 LLM 压缩可达，解压分钟级，与详情页冲突。
3. **词级码本、全局 zstd 字典、多书合并都实测无效或收益 <1 个点**——LZ 已经吃掉了那部分冗余。
4. 唯一还没吃的大块是**章节去重**：全库 37,547 章重复（412 MB / 8.5%），属于存储结构优化。

## 1. 现状

正文按 1 MB 块 zstd-best 存储（首字节标记 0x02），全库 5,130 块、1.69 GB（原始 4.87 GB，**34.7%**），
VACUUM 后全库 1.62 GB。详情页读一章 = 解压所在块 ≈ 1 ms。

## 2. 实验方法

- **样本**：真实库随机取 12 本（2–12 MB/本，合计 74.5 MB），逐块解压还原原文后重压。
- **全库验证**：均匀抽样 200 本（1.23 GB），避免 12 本样本的「同源相似」偏差。
- **对照**：纯 Go（`klauspost/zstd`、`andybalholm/brotli`）与 CLI（zstd -22、xz -9e、brotli q11、7zz PPMd、zpaq -m5）分开跑，
  防止把 C 库数字当成纯 Go 能力。
- 所有方案均做**往返校验**（解压后逐字节比对），码本类方案额外验证解码可逆。

## 3. 算法与编码实测（12 本样本口径；标注「全库」的行来自 200 本验证）

| 方案 | 压缩率 | 压缩速度 | 解压速度 | 纯 Go | 容器 |
|---|---|---|---|---|---|
| 现状 1 MB 块 zstd-best | 34.7%（全库） | 21 MB/s | ~1 GB/s | ✅ | ✅ |
| 整本 zstd-best | 32.2% | 21 MB/s | ~800 MB/s | ✅ | ✅ |
| GB18030 + zstd-best | 29.3% | 28 MB/s | ~800 MB/s | ✅ | ✅ |
| brotli q11 | 27.9% | 0.52 MB/s | 136 MB/s | ✅ | ✅ |
| **全局字码本 + zstd** | **26.8%**（全库 200 本） | 21 MB/s | ~800 MB/s | ✅ | ✅ |
| GB18030 + brotli q11 | ~26.7% | 0.5 MB/s | 130 MB/s | ✅ | ✅ |
| GB18030 + PPMd | 22.5% | 4.4 MB/s | 4.0 MB/s | ❌ CLI | ⚠️ 装 7zip |
| zpaq -m5（CM） | 20.4% | 0.34 MB/s | 0.34 MB/s | ❌ CLI | ❌ |
| xz -9e（纯 Go） | 27.9% | 极慢 | **0.24 s/9.5MB** | ⚠️ | ❌ |
| 词级码本 + zstd | 28.5–29.2% | — | — | ✅ | ✅ |
| 12 本合并（码本 + zstd） | 23.9%（样本特例） | — | 差 | ✅ | ✅ |
| 全库 200 本合并 | 26.5% | — | 差 | ✅ | ✅ |

要点：
- **码本设计**：全库字频排序，前 192 字 → 1 字节（0x00–0xBF），其余 → 2 字节（0xC0–0xFE +
  次字节），长尾 → 三字节转义。全库 33,941 个字符、平均 **1.36 字节/字**（UTF-8 为 3）。
- **词级码本更差**（28.5%）：把高频词组替换成低频码位，破坏了 zstd 已经能匹配的重复串。
- **全局 zstd 字典只省 1.3%**（跨书训练 112 KB 字典，1 MB 块）：窗口本来够大。
- **合并收益是假象**：12 本样本合并从 27.65%→23.90%，但全库 200 本只从 26.82%→26.51%，
  样本同源相似度远高于全库。

## 4. 结构层

| 方案 | 收益 | 代价 |
|---|---|---|
| 正文移出 SQLite（每本一个压缩文件） | 压缩率不变，SQLite 从 1.62 GB → ~0.1 GB | 备份/恢复流程改 |
| 1 MB → 8 MB 块 | 34.7% → ~32.5%（外推） | 详情页 8 ms |
| 整本压缩 | 32.2% | 详情页 10–25 ms |
| 章节去重（37,547 章 / 412 MB） | 再省 ~100–120 MB | 内容寻址存储，复杂度高 |

## 5. 熵与理论上限（全库 16.58 亿字符实测）

| 层级 | bits/字 | 对应 UTF-8 比例 |
|---|---|---|
| 无上下文最优编码（字频熵 9.17） | 9.17 | 38.2% |
| **1 阶上下文（bigram 条件熵 6.32）** | **6.32** | **26.3%** |
| 码本 + zstd（实测） | 6.4 | 26.8% |
| GB18030 + PPMd（实测） | 5.4 | 22.5% |
| zpaq CM（实测） | 4.9 | 20.4% |
| LLM 压缩（文献） | ~2.4 | 8–12% |

结论：**码本 + zstd 已经≈1 阶极限**；字级编码最多再压 0.1–0.2 字节/字，再低必须高阶上下文模型。
全库字符分布：top 100 覆盖 52.4%、top 1000 覆盖 89.3%、top 5000 覆盖 99.89%。

## 6. 文献

- LZ 类（zstd/brotli/xz）：中文 26–32%，与实测一致；xz 只比 zstd 好 0.5–1.5 点。
- PPM 类：中文 20–23%（PPMd/PPMII）；中文大字符集是压缩的天然难点（[Bangor 博士论文](https://research.bangor.ac.uk/portal/files/70857215/PEILIANG_WU_PhD_2007_-_OCR.pdf)）。
- 词级大字符集 + 二阶预测（[NTUST](https://etheses.lib.ntust.edu.tw/thesis/detail/499ac9567f23b608b67a188b80bcc6e5/)）：与通用 PPM 同量级，无突破。
- CM 类：19–21%，解压 0.3 MB/s 量级。
- NN 压缩：[LMCompress（Nature MI 2025）](https://arxiv.org/abs/2407.07723) 称文本压缩率约为 bz2 的 1/4（中文对应 7–10%），
  解压需逐字符模型推理；[ALCZip](https://ieeexplore.ieee.org/abstract/document/10929277) 同类。
- 中文小说领域**没有**成熟专用算法；研究主线就是「大字符集 + 词级建模」。

## 7. 方案矩阵（按你的约束：纯 Go、Docker、详情页解压）

| 档位 | 方案 | 压缩率 | 详情页 | 迁移 |
|---|---|---|---|---|
| 推荐 | 码本 + 整本 zstd | **26.8%** | 15–25 ms | ~10–20 min |
| 极限（慢） | 码本 + brotli q11 | ~24.4% | 100–250 ms（NAS） | ~2.6 h |
| 外部 CLI | GB18030 + PPMd | 22.5% | 3–10 s | ~1 h |
| 研究级 | zpaq/paq8 | 19–20.4% | 15–40 s | 数小时 |
| 不可行 | cmix / LLM | 8–12% | 分钟–小时 | 需 GPU |

## 8. 推荐路线

1. **阶段一（低风险）**：全局码本（1.36 字节/字）+ 正文移出 SQLite + 每本整本 zstd。
   目标 26.8%，详情页 15–25 ms，容器零额外依赖。
2. **阶段二（可选）**：若详情页能接受 200 ms，切 brotli q11，目标 ~24.4%。
3. **阶段三（独立）**：章节去重，目标再省 100–120 MB。
4. **不做**：词级码本（更差）、全局 zstd 字典（1.3%）、多书合并（0.31 点）、xz/PPMd/zpaq（解压不可接受）、LLM 压缩。

## 9. 风险

- **码本版本化**：新导入的书带新字符时走三字节转义；需要定期重建码本 + 全库重压（10–20 min）。
- **全库字符集 33,941**：三字节长尾必须设计好，否则转义率上升吃掉收益。
- **迁移窗口**：全库重压期间不监听端口（沿用一次性容器预跑 migrate 的既有做法）。
- **兼容**：老块 0x02 保留读路径，新格式用 0x03（码本流），支持混存渐进迁移。
- **内存**：整本解压后码本解码放大 2.2 倍，注意并发峰值。
