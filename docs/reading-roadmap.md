# 阅读体验对标与优化路线

> 基线 0.13.5。本文只写**决策**：先做哪个、为什么、怎么验收。完整能力矩阵与全部来源在 [reading-benchmark](reading-benchmark.md)，阅读器现状在 [reading](reading.md)——同一信息不在三份文档里重复。

## 1. 结论先行

- **书库侧已过线**：章级指纹判重、系列聚合、元数据补全、五种翻页、段级进度、账号级设置同步都在同类前列。
- **标注与检索侧是短板**：划线/笔记、字典翻译、跨章检索三块全空——缺的是「读完一本书之后」的知识沉淀层。
- **社区层不做**：热门划线、段评/章评、书评依赖平台内容规模，自托管单机书库没有这个前提。
- 顺序：先修**已宣布但只落地一半**的 7 项（便宜、可感知），再做**分页可选词**（标注能力的总入口），最后才是**标注层**（唯一的 L 级投入）。

## 2. 差距从哪来

矩阵全量（13 家 × 24 项，含逐格来源编号）见 [reading-benchmark](reading-benchmark.md)。决定优先级的只有一句话：

> **「读书时」的能力我们已经不弱；「读完以后」的能力基本为空。** 划线/笔记、查词翻译、跨章检索三块在几乎所有同类产品里都有，我们一个都没有。

我们反而占先的差异化（可进发布说明）：五种翻页效果、自动滚动 + 滚到底自动翻章、段级进度、排版设置按账号同步、书签导出 MD/JSON、章级指纹判重。

## 3. 差距优先级

成本口径：**S** ≤1 天（单文件或单条 CSS，复用现有接口）｜**M** 2–5 天（新组件或新接口，不动 schema）｜**L** >1 周（新表 + 迁移 + 双模式交互 + 导出）。

### P0（先做，缺了就撑不起「阅读器」定位）

- **划线 / 笔记 / 标注导出**：读者价值＝读完能带走句子，是「书库」变「书房」的分界。现状 28 个迁移无批注表、书签之外无注记路由（`internal/api/server.go:175`）。成本 **L**（新表 + 迁移 + API + 双模式选中态 + 导出）。前置：分页可选词先落地，段落定位口径两模式统一。
- **分页模式下可选词**：读者价值＝分页是手机主路径，现在连复制/查词都做不到，且这是所有标注能力的入口。现状 `.reader-paged{user-select:none}`（`web/src/styles/ix-reader-paging.css:27`）。成本 **M**（一行 CSS 不难，难在三区点击与长按选中的手势冲突、读屏取词回归）。前置：定手势优先级——长按走选词，单击仍翻页或呼控制栏。
- **跨章 / 全书内检索**：读者价值＝翻章找句子是当前最具体的降级体验。现状 `readerSearch` 只在当前章内存匹配（`web/src/lib/readerSearch.ts:4`），后端 `Search` 只按书名（`internal/store/search.go:32`）。成本 **M**（按需：打开一本书时流式扫描该书正文，索引只活在会话里）。前置：先按 ADR-0002 口径算体积与首查时延——正文索引曾占全库 65%，**常驻全库索引不做**。

### P1（做完 P0 才放大价值）

- **字典 / 翻译 / 生词本**：读者价值＝中文场景查多音字、成语、生词。现状无选词菜单（`web/src/features/reader/ReaderTapZone.tsx:26` 只处理 pointer）。成本 **M**（选词浮层 + 词库来源 + 生词本复用现有表结构）。前置：分页可选词。
- **TTS 定时关闭 / 熄屏续播**：读者价值＝睡前是听书主场景，Web Speech 熄屏即停。现状控制条无定时项（`web/src/features/reader/ReaderTtsBar.tsx:10`）。成本 **M**（定时与音量渐弱在前端；熄屏续播要外部 HTTP 引擎 + 后台音频策略）。前置：外部引擎先能被选到（见 §4）。
- **全局标注 / 书签页**：读者价值＝跨书找回自己的笔记，否则只是「书内抽屉」。现状 `web/src/routes.tsx` 无书签路由，书签只作抽屉第二页签。成本 **S**（复用列表组件 + 一条查询接口）。前置：P0 标注表落地后扩来源。

### P2（候选池，先不进排期）

- **竖排 / 双列**：价值＝古籍、繁体与横向大屏。现状全仓无 `writing-mode`，分页靠 `column-width` 分栏（`web/src/styles/ix-reader-paging.css:75`）。成本 **L**（字排线是自研分栏，竖排要重做测量与翻页引擎）。
- **X-Ray 类人物速查**：价值＝长篇人物关系一屏可查。现状 AI 辅读只有整章 / 选中段 / 问答（`web/src/lib/aiReading.ts:48`），无实体索引层。成本 **M**（复用 AI 通道做抽取 + 本地缓存）。前置：AI 开关真正生效（见 §4）。
- **阅读目标 / 打卡**：价值＝把已有热力图变成闭环。现状只有时长统计无目标（`web/src/lib/readingTimer.ts`）。成本 **S**（目标存设置 + 当日聚合查询）。
- **脚注 popover**：价值＝注释就地展开。现状 TXT 语料没有注释结构，只有 EPUB 才有锚点。成本 **M**，因此排最后。

## 5. 差异化卖点（值得写进 README 与发布说明）

- **一个 Web 阅读器给满五种翻页效果**（slide / cover / fade / curl / none）：开源侧只给「翻页模式」切换，商业侧止于三种左右。
- **自动滚动 + 滚到底自动翻章**：竞品的自动翻页多为开关式，滚动流里跨章续读少见。
- **段级进度恢复**：多数竞品按位置百分比，长章中文网文下段级更实用。
- **阅读设置按账号同步**：同类开源产品明确停在 localStorage。
- **书签可导出 MD / JSON**：竞品导出普遍面向标注，书签单独结构化导出少见。
- **章级指纹判重 + 版本择优**：同类只有元数据级查重，按正文判重是大库场景的真实门槛。

## 6. 明确不做

- **社区划线 / 段评 / 书评**：价值来自平台规模，单机书库的热门划线只会是零。
- **常驻式正文全文索引**：除非拿出新的体积与延迟实测（ADR-0002 的 65% 教训），否则默认不做。
- **任何需要联网账号体系的能力**：云端书架、书城、共读。
- **评论类社交与好友动态**：与「自托管私人书库」的定位冲突。

## 7. 分期路线

| 版本 | 内容 | 验收判据 |
|---|---|---|
| 0.14 | §4 的 R1–R7 全修；分页可选词；主题同步口径对齐 | `make gate` 9 项全绿 + 前端覆盖率不低于基线；可选词、自动滚动各进 `make audit-reader` 一条不变量；主题同步一条 vitest |
| 0.15 | 标注表 + 划线 / 笔记 + 导出（MD / JSON）+ 全局标注页 + 书签 label 编辑 | 迁移只前进且迁移后跑 VACUUM；导出格式有快照测试；分页与滚动两模式各 1 条 audit 不变量 |
| 0.16+ | 全书内检索（先出体积与首查时延实测 + ADR 附注）；字典 / 翻译；TTS 定时与熄屏 | 检索先给成本实测再定是否常驻；新能力都进 `make audit-reader` 或前端 vitest 覆盖 |

## 8. 复测口径

- **入口**：按 §2 列出的来源 URL 逐格核对（差一格更新一格，不整表重写）；norvels 自己那一列用 `make audit-reader` 复核，新增能力先有 `文件:行` 证据再进表。
- **取证顺序**：官方 README / 帮助页 / 商店描述优先，第三方只作佐证；取不到原文一律记「未确认」，不按「应该有」推断。
- **口径对齐**：成本档位与 §3 定义一致；上线前一律过 [quality-gates](quality-gates.md) 的 9 项门禁与前端覆盖率基线。
