## 已拍板（用户 / lead 明确给出）

- 目标平台：web，一份产物内部做响应式适配（1440 / 1024 / 768 / 390 四个断点）。
- 画布：1440×900；语言 zh-CN；交付形态为可交互单文件 HTML 原型（CSS 内联、不引 CDN）。

## 0.6 端职责分化（2026-10-24 用户拍板）

**PC（≥1024）＝ 全功能工作台，H5（≤768，重点 390）＝ 轻量阅读器。**
这不是「同一条数据换密度」，而是两套信息架构：管理能力只属于 PC。

| 能力 | PC ≥1024 | H5 ≤768 |
|---|---|---|
| 书架网格 / 列表切换 | ✅ | 仅单列简表（无网格/列表切换） |
| 排序 / 作者筛选 / 标签 | ✅ 工具栏常驻 | 仅「继续阅读 + 最近在读」，筛选收进弹层或不做 |
| 分页 | ✅ | 不做分页，改为无限滚动或只给最近 N 本 |
| **导入管理**（表单 / 进度 / 失败明细 / 任务历史） | ✅ | ❌ 完全不出现在导航与任何入口 |
| **作者管理** | ✅ | ❌ 完全不出现在导航与任何入口 |
| 批量操作 / 表格视图 | ✅ | ❌ |
| 搜索（书名 + 章节两栏 + 片段高亮） | ✅ | ✅ 轻量版：单一输入框 + 结果列表，命中片段仍高亮 |
| 书籍详情 | ✅ 双栏 | ✅ 单列，简介折叠 |
| **阅读器** | ✅ 目录常驻、设置面板、三主题、键盘 ←/→/空格、进度恢复 | ✅ **同等功能**：目录全屏抽屉、设置底部面板、三主题、左右滑动翻页、进度恢复 |

判据：
1. 390 下**看不到任何管理类入口**（导入 / 作者 / 批量）——不是藏起来，是不渲染。
2. 1440 下管理能力全开，导入页可见进度与失败明细。
3. 阅读器两端能力等价，只换入口形态（阅读是产品核心，不因窄屏砍能力）。
4. H5 首屏信息顺序：继续阅读 → 最近在读 → 搜索入口 → 书架列表。

## 0.6 H5 与 PC 职责分化（用户指令 2026-10-24）

同一份产物、两套信息架构——**不是**「大屏多两列」的响应式缩水。实现方式是断点 + 少量 JS 决定**哪些区块进 DOM**（H5 下移除，而非 display:none）。

| 图层 | PC（≥1024）全功能工作台 | H5（≤768，重点 390）轻量阅读器 |
|---|---|---|
| 首屏 | 书架网格 + 工具条 + 侧栏导航 | 继续阅读大卡 + 轻量搜索 + 最近在读 |
| 书架 | 网格/列表切换、排序、作者筛选、标签、分页 | 单列简表（封面 36px、无简介、无工具条） |
| 作者管理 | 有（表格） | **不渲染**（DOM 移除） |
| 导入管理 | 有（表单/进度/失败明细/任务历史） | **不渲染**（DOM 移除） |
| 搜索 | 书名 + 章节两栏 | 单列（两栏收成一列） |

## 0.7 断点自检清单（每轮交付前逐条跑）

> 这些是实测踩过的坑，不是理论条目。每条都给可执行的断言。

| # | 检查项 | 判据 | 断言 |
|---|---|---|---|
| 1 | 横向溢出 | 四断点 `scrollWidth - innerWidth === 0` | `document.documentElement.scrollWidth-innerWidth` |
| 2 | **flex 子元素含 CJK 必须 nowrap** | flex 行内 chip / tab / 按钮组不得逐字换行 | `[...document.querySelectorAll(".vol-jump > *, .chips > *, .search-tabs > *")].every(a => a.getBoundingClientRect().height < 60)` |
| 3 | 封面类不放大 | `width:100%` + `aspect-ratio` 在窄屏不得撑满整行 | `.cover` 宽度 ≤96px（390 断点） |
| 4 | grid 列不被内容撑破 | 单列断点用 `minmax(0,1fr)` 而非 `1fr` | `getComputedStyle(el).gridTemplateColumns` 不超过视口 |
| 5 | 长列表不进全量 DOM | 1000+ 章只渲染视口 ±20 | `querySelectorAll('.cv-row').length < 100` |

**第 2 条的由来**：`.vol-jump` 的 CSS 只写了 `.vol-jump a`，而 JS 渲染的是 `<button>`，样式没命中 → 12 个 chip 被 flex 压到 27px 宽，中文逐字换行，高度爆到 165px。同类问题也出现在 `.dir-head h2`（被 `margin-left:auto` 的兄弟挤扁）。**修法**：容器侧 `flex:0 0 auto` + `white-space:nowrap` + `word-break:keep-all`，放不下就横向滚动或换行，绝不允许压缩。

| 6 | **无重复信息** | 同一视口内 `.num` / `.meta` / `.pill` 文本不得出现 ≥2 次 | `window.__auditDuplicates('<view>')` 返回空数组 |

**第 6 条的由来**：目录行曾同时输出 `<span class="num">3634</span>` 和「第3634章 长街」，章号印两遍；导入页的「289 / 20 / 运行中」在进度卡与任务历史里各出现一次。修法是**同一信息只在一个层级出现**——目录行只留完整标题，当前任务由进度卡独占、历史表只列已结束任务。

**实现**：查重函数已内置于产物（`window.__auditDuplicates(view)`），可随时在 console 复跑；六视图当前均为空数组。

| 7 | **无非用户语言** | 可见文案不得出现实现词 | `document.body.innerText` 匹配词表，命中数 = 0 |

**第 7 条的由来**：早期 UI 外露了 SQLite / FTS5 / 虚拟滚动 / 渲染 / 编码 / SHA-256 / OOM / 幂等 / 用时 0.08s 等实现细节。用户的原话是「把我们内部使用的一些 id 啥的尽量别外露，标准一点」。

**词表**（可跑断言）：`SQLite|FTS5|DOM|虚拟滚动|渲染|索引|编码|SHA-256|OOM|幂等|断点续跑|gb18030|bookId|用时|字级|并发|localStorage|API|GET |POST |409|token\b|原型|演示`

**改法口径**：
- 实现细节 → 用户结果：「SHA-256 幂等」→「同一文件不会重复导入」
- 错误术语 → 人话：「编码探测失败」→「文件格式无法识别，可能已损坏」
- 内部状态 → 用户语言：「已解析」→「已入库」；「运行中」→「处理中」
- 性能指标不进 UI：「用时 0.08s」直接删
- 产品定位可以说，但不能用实现词：「SQLite · FTS5 · 本地运行」→「所有数据保存在你的电脑里」
